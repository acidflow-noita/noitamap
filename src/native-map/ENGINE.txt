Independent world generator, first implementation

world.ts owns preparation and generation orchestration. asset-host.ts accepts a
versioned, explicit asset reader. rules/ contains owned/adapted deterministic
rules and tables with upstream provenance and license; it imports no Telescope
application or renderer. The worker build rejects those dependencies, including
lazy imports. Browser delivery reuses Noitamap's existing immutable asset pages
without installing fetch interceptors or browser shims.

One generator lives in each persistent worker. Requests are queued; seed,
unlocks, mode and seasonal calendar are captured for each request. Cancellation
is observed at region boundaries. Immutable assets survive seed changes; generated
geometry buffers transfer to the client. Shared scene masks never transfer.
A failed preparation causes the client to replace the worker before retrying.

world-pool.ts now distributes horizontal worlds across persistent owned workers,
joining all requested Main/Heaven/Hell decisions before returning. Unknown/two-core
or <=2 GiB devices use one worker; four-core or reported <=4 GiB devices cap at
two; other devices use at most three. Light mode uses one. Inputs are snapshotted
before preparation, results retain requested region order, and cancellation or a
worker failure retires the whole request without accepting late sibling output.
Only the primary worker returns geometry buffers. Each worker currently builds
its own geometry/prescan internally; sharing that work remains a future change.

2026-10-14 local Node worker diagnostics: normal multiworld requests took
543–773 ms with one worker versus 285–500 ms with three. The compiled production
pool also matched six normal/restricted/NG+/Nightmare/reordered/Light requests;
its warmed normal samples measured 557–635 ms serial versus 279–390 ms parallel.
The first production-pool comparison was 932/927 ms under concurrent validation
work, so these results do not establish a cold-start improvement. Timings cover
generation and messaging, not shader startup, presentation or all-nine cooking.
Initial retained worker heap+ArrayBuffers were about70 MiB for one versus178 MiB
for three in the standalone diagnostic; transient generation allocations are
higher and browser usage may differ. Hardware selection bounds this tradeoff.

The presentation profiler now follows the live HD route through backgrounds,
terrain, scenes and marker drawing. In four isolated native processes (1/3/3/1
generation workers, Mesa shader cache disabled), median warm presentation was
1326 ms with one worker versus1045 ms with three. First-use medians were4310 ms
versus4115 ms. All viewport hashes matched. This is a fixed-camera native GLES
comparison, not Firefox timing or an all-nine pixel cook. Sampled process RSS
was roughly1.4–1.7 GiB versus1.8–2.1 GiB; that includes Node and software GLES,
not just the worker heaps, and is not a browser-memory estimate.

For single-worker requests, geometry is now handed off after spawn prescanning,
before placement scans. The worker transfers large layer buffers once and retains
its small biome map; its final message carries placements. The client joins both
messages using the same geometry objects. Cancellation and final identity checks
still apply. GPU preparation can overlap placements; presentation still waits for
all scenes and the existing complete-frame barrier. Multiworker requests retain
the previous handoff timing because the measured overlap gain was inconclusive.
Paired single-worker presentation tests saved about208 ms on first use and94 ms
on warm seed changes (medians). This is incremental, not the instant-map goal.
Normal/restricted/seasonal-NG+/Nightmare/reordered-world/Light data match the
non-streaming control. The existing12completed-tile reference also matches.

Run node build_scripts/profile-map-presentation.mjs for the native presentation
comparison; build_scripts/map-presentation-profile.txt describes controls and limits.

Output: native-world-description, containing geometry, elevator continuation,
and separate POI/scene records for West/Main/East x Heaven/Main/Hell. It deliberately
is not a completed image or tile source. The final material/scene/liquid/edge/POI
composition and all zoom levels still need the independent GPU cooking pipeline.
The existing HD map now obtains its generation data from this worker through
the existing Noitamap adapter. The adapter retains the site's orb/boss/perk/marker
postprocessing and supplies the existing renderer, so the UI and map controls stay
the same. Approximate mode keeps its prior generation path. There is no separate
generator page. The independent final-pixel GPU cooker remains unfinished.

An owned GPU renderer now lives in gpu/. The existing HD map selects it on
detected hardware GPUs. terrain-renderer=native/legacy can override selection
after a reload; software/unknown adapters retain the legacy default. It splits material
resolution from color/liquid composition and owns its contexts/programs/targets;
input builders and higher-level scene/edge/marker composition remain shared with
the current host. Arithmetic attribution and the preparation script are recorded
in gpu/PROVENANCE.txt. This replaces rendering of requested rectangles, not the
complete all-nine cooker. The user's Windows/Firefox test reduced shader startup
from 7.918s to 2.068s. New-seed first paint was 1.35s. Software-GPU warm frame cost
regressed in native GLES, which is why that default remains separate.

Browser inputs include explicitly emitted wand sprite distributions and RNG data,
in addition to the existing immutable game-asset pages. Tests boot the actual
production worker using emitted files only; source-directory reads cannot mask
a missing deployment asset. No browser automation was performed.

Verification: real worker differential comparison of all nine scene/POI regions
for normal, restricted unlocks, NG+ plus seasonal rules, and Nightmare. It also
transfers returned geometry away before reseeding to catch detached input buffers.
Owned generation runs with browser globals and implicit fetch made unusable.
Existing geometry fixtures additionally cover pinned Lymm and render-perf outputs.
Production pool tests compare full geometry and ordered scene/POI data across
actual emitted workers, including restricted unlocks, seasonal NG+, Nightmare,
nonstandard world ordering and Light mode. Lifecycle tests cover cancellation,
worker failure, input mutation, mismatched responses and disposal during work.
The normal map integration also matches frozen pre-change metadata and12completed
512-square terrain/scene tiles across two seeds and full/Light world selection.
This establishes compatibility for those cases, not complete game-capture fidelity.

Accuracy authority remains versioned Noita behavior/captures. Current translated
rules preserve known source behavior, including existing compatibility choices;
removing their known inaccuracies still requires targeted RE/game evidence.

Independent completed-pixel components (not enabled in the live map)

complete-materials/ owns the full scalar material WASM resolver, explicit
unresolved classifications, topology0 inputs, vertical-plane/shaft handling,
noise-density and band selection. cook-inputs/ supplies owned lattice, atlas,
legacy-color and foreground preparation. composition/ owns scene-source loading,
whole-scene preparation, liquids, backgrounds, ownership, static masks and
ordered world/seam/scene edge stamping. complete-world/ assembles those inputs
from native-world-description into exact terrain/scenes-layer pages for all
nine region addresses. Static captured artwork and POI drawing remain separate
host layers; transparent capture cutouts are not newly generated artwork.

A new seed20261014 passes11 actual completed-page comparisons spanning all nine
regions, vault and a continued shaft:11,534,336 native RGBA bytes and110 stored
mip levels match the independent CPU/JS-edge reference. Separate seed1337
composition comparisons cover16 pages and15,796,236 RGBA bytes. The source's
measured setup was2096ms and sampled page rasterization89–244ms. These costs
confirm that a full scalar bake cannot be the instant new-seed implementation.

cooked-pixels/ stores immutable final fragments, shares a prepared baseline
between independent seed stores, and seals every required page and global mip
before exposing a map. prepared-world/ composes constant/single-selector image
alternatives during preparation, then binds the current seed into those final
pixels. Its all-page owner rejects unprepared coverage when the reference-work
budget is zero. cooked-view/ decodes sealed maps for OSD and stores reusable
libraries separately from completed seeds. Neither decoder invokes generation.

The missing performance-critical piece is the complete reusable Noita recipe
catalog and its exact seed-dependent boundary/scene/edge bindings. No all-nine
instant Noita cook is claimed by the generic compiler tests. These new engine
components are not a deployable speed improvement yet; current site behavior
and its existing renderer remain active. See prepared-world/README.txt for the
preparation contract and complete-world/parity-result.json for measured scope.
