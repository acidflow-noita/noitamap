Runtime material interval certificate -- admitted scope and proof obligations

Target is the unchanged owned complete-materials C scalar resolver, including
its ordered f32/f64 casts, and the consuming runtime's Math.sin/cos inputs. This
does not make inherited game rules/cave state more accurate than that resolver.
No already-rendered seed or per-variant image catalog is used.

Why ordinary floating shaders are insufficient
WGSL permits reassociation/fusion and does not mandate a rounding direction.
Native f32 equality tests cannot establish portable source-bit parity. See
https://www.w3.org/TR/WGSL/#floating-point-evaluation (15.7.2 through15.7.5).
The candidate therefore accepts an integer MATERIAL ID only when every value
inside conservative numerical intervals selects that same result. It never
publishes approximate coordinates, coverage, density or a guessed material.

1. Exact one-dimensional inputs
The host evaluates the C reference's binary64 coordinate products and explicit
f32 casts in the same order. It uploads nominal lattice cells, noise coordinates,
rare-polkapixel coordinates/residues and exact f32 coverage parameters. Raw
ownership sin/cos*30 inputs are enclosed by adjacent f32 endpoints. These are
O(width+height) arrays for the bands reachable from this rectangle's chunk
neighborhood. There is no native-pixel noise array or cross-seed variant table.

2. Outward operations
For bounded finite normal values, WGSL add/subtract/multiply returns one of the
two adjacent f32 results surrounding the exact real operation. Moving down/up
one representable number encloses that real result. It also encloses the source
operation rounded to either binary32 or binary64: each endpoint is representable
in both formats and rounding is monotone. Min/max endpoint products handle all
sign combinations; squaring uses its actual nonnegative range.

Each ordered operation is followed by observable integer bit manipulation of
its endpoints. These are part of the algorithm's semantics, not a requested
optimization hint. Reassociation cannot cross those integer steps while retaining
the required integer results. Intermediate shader arithmetic remains finite.

Subnormal operation results, including permitted flush-to-zero, expand to at
least[-minimumNormal,+minimumNormal]. At the minimum-normal boundary the outward
normal neighbor is retained; the inward subnormal endpoint is widened to zero.
This prevents an inward bound if an exact result lies just beyond minimumNormal.
Raw subnormal coverage words are detected BEFORE conversion and sent to exact
correction. Subnormal sampler parameters reject explicitly. Other initial point
inputs are normal or zero in the fixed source tables and integer coordinate
domain; the rectangle guard keeps integer coordinate conversions exact.

Division is used only for positive polka radius. Eight adjacent-float steps on
both sides conservatively cover WGSL's2.5ULP allowance and the source rounding,
including an exponent boundary. Tiny denominators/large numerators are rejected
to correction before division, so overflow/finite-math assumptions cannot admit
an invalid result. Fixed known-zero, sign, and unit operations remain exact.

3. Control-flow certificate
Lattice floors, simplex triangle choices, ownership chunk truncation, nearest
material rounding, coverage thresholds, ordered density bands, rare gates and
geometry predicates must agree over the entire interval. Otherwise a reason-tagged
pixel index is appended to the exact correction list. An ambiguous branch never
gets a silent guessed answer. Reference double band thresholds are converted to
equivalent inclusive/exclusive f32 cutoffs because the selected density is f32.

Non-bilinear Wang samplers are admitted by the later certificate in section9.
The2026-10-14 extension admits topology0 branches using C-derived inputs and
the same interval proof; see sections6/7. Required cave pixels are computed and certified or repaired,
never removed by an ownership/static policy change.

4. Narrow exact integer hash
Polka hash rounding is deliberately discontinuous; wide numerical intervals there
would be ineffective. Authored phase residues bound a to25..97,b to160..232. Both
squares are exact integers and their product is below2^29. Integer ties-to-even
conversion yields the source f32 base. A24x24-bit significand product is split into
16-bit pieces, preserving all48 bits; integer guard/remainder/tie logic produces
the exact four positive-normal f32 hash products. All5,329 residue pairs and all
four source constants are checked exhaustively (21,316 products). Values outside
the proved finite positive-normal domain go to correction. This is not a general
software floating-point interpreter.

5. Exact completion
The GPU list stores one pixel index and reason tag for each rejected candidate.
Only that compact list is read back. correct.c wraps the unchanged scalar C
implementation in ONE batched call per rectangle, retaining exact source casts
and shared per-column surface/trig preparation. It returns material/class/owner
records; unavailable input/unsupported reference classifications throw.
Indexed GPU patches complete before resolvePage/resolveRect returns ready.
No-uncertainty output and every repaired output are checked against the complete
scalar oracle. Legitimate legacy=-1 and force-air=0 remain their original policy.

6. Source-derived cave inputs and arithmetic
The C wrapper exports readonly Topo0/Surface structs with compile-time ABI size
assertions. Config values are enclosed by adjacent f32 endpoints. Four named
modifier grids and the immutable finite sin-hash table use original source
bytes; raw subnormal/nonfinite table words reject before arithmetic. The host
computes each material/modifier/carve coordinate in the same ordered f64/f32
cast sequence as topo0.c, for O(width+height) axes. Only reachable topology0
config families receive arrays. No per-pixel material/noise table is uploaded.

Surface lines use the original C surface_line/prepare_surfaces once per column,
with outward f32 bounds on the resulting double top/bottom values. Type3 carve
prefix values come from the same finite C trig tables, with adjacent bounds;
missing/subnormal prefixes reject. Shader modifier smooth interpolation, noise
blend, depth interpolation/division, FBM rotations/octaves, clamping/scaling,
carve types0/3 and the final ordered weighted sum enclose every source operation.
The FBM runtime loop preserves four ordered octaves and exact powers-of-two
weights. Hash coordinates remain exact bounded integers in the admitted main
plane; accesses outside the original finite hash range reject.

Every source branch is either enclosed by a monotone operation (clamp/max) or
agrees across the interval: modifier<1, modifier/depth>0, surface comparisons,
depth noise/carve gates and band membership. Numerically ambiguous cave predicates
use reason256. Unsupported edge2, depth_blend, unknown noise/modifier kinds or
missing grids use reason512 and exact completion; source failures still throw.
This extends the previous certificate without a general floating interpreter.

The compact C repair batch selects the identical grid/mode for each index.

8. Exact legacy foreground completion
Original material IDs preserve classifications and edge/liquid policy. A ready
material=-1 is not an RGBA decision: the complete-world base painter invokes its
legacy color sampler for classifications3..7. The optional legacy extension
therefore collects negative IDs onGPU, reclassifies that compact list through
the same retained exact C resolver, and calls unchanged legacy.colorAt only for
classes3..7. Classification0..2 remains zero even for a synthetic negative ID;
source failures cannot publish ready output. Integer ARGB-to-RGBA byte exchange
and indexed GPU patches preserve colors, including flat alpha semantics.

No numerical claim about a native-float legacy shader is introduced. The legacy
sampler has different local-plane and unsigned-noise rules; those remain in the
original owned JavaScript. The new GPU code only performs integer collection
and scatter. Tests cover allfour failed fullshaft color fields, strict outside
classification filtering, output elision, unchanged material bytes and three

9. Coverage-edge and material-edge samplers
The source evaluates shifted coordinates as f64(f32Coordinate)+0.5, floors in
f64, and then uses either f32 fractions/type1 or f64 fractions/type2. Existing
outward interval operations enclose these shifts/subtractions and monotone
source casts. No fraction is guessed from an approximate shader coordinate.
Both shifted floors must agree; otherwise reason1 repairs the sample.

After floors agree, the center coverage word is compared strictly>0.5 and all
side/diagonal words use the original>=0.5 or<0.5 condition. Lattice words are
exact f32 inputs, with raw subnormal words rejected before conversion. Material
labels are exact unsigned16-bit integers. Toroidal accesses use the selected
main/shaft descriptor exactly as the already-certified bilinear sampler does.
The comparisons fx>=fy,1-fx<=fy,fx>=0.5,fy>=0.5(type1) and fx>=fy,1-fx>=fy(type2)
must agree across interval endpoints, including the different source rounding
steps. Otherwise reason16 repairs the sample. Stable control flow publishes
point(0) or point(1); the existing threshold/nearest-label/density/band pipeline
then consumes that exact coverage. Type0 bilinear behavior remains unchanged.

Direct original-C sampler probes and actual WGSL cover36,935cases/37,387source
queries, including deliberately different f32/f64 fractional-tie outcomes.
34full canonical fields across two seeds/all9positions/shafts match the full C
resolver with no pending or padding differences. The old blanket sampler repair
has been removed; other reason128 rejection conditions remain present and tested.

10. Bounded one-dimensional input reuse
The axis cache stores exact words produced by the existing host/C one-dimensional
builders. An immutable key includes axis direction, origin, length and every
used coordinate coefficient; negative zero remains distinct. Cave/surface/carve
entries carry a unique engine scope, which is removed on engine disposal rather
than identified by seed alone. This also isolates custom carve tables and named
imported-state offsets. The cache cannot change arithmetic or shader predicates.

Query headers, offsets and upload arrays are rebuilt in original order. All
cached words are copied before any per-query shaft-nearest modification. The
CPU-only test compares every word and layout offset against the preserved old
builder plus uncached current builder for both actual full all-nine page sets,
with bounded eviction, mutation, shaft and imported-state isolation checks.
No rendered-field cache or coordinate/permutation catalog is introduced.
