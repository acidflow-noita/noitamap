Final-pixel storage and mip atlas

Scope
  pixel-storage.ts defines a flat lossless 8x8 block format and CPU roundtrip
  oracle, plus WGSL encode/decode. Colors are final RGBA bytes, not material IDs.
  pixel-storage-gpu.ts constructs compact GPU buffers in bounded batches.
  mip-atlas.ts packs three completed 512 px pages and their exact 512..1 mip levels
  into one 1024x1024 atlas. It creates no mip levels and changes no pixels.
  No module contains Noita generation logic, prerendered alternatives, seed
  history, persistent caching, PNG encoding, or a live application import.

Format and bounds
  R occupies bits 0..7, then G, B, A. Hidden RGB under alpha 0 is preserved.
  Each 8x8 block has one u32 directory entry: high 3 bits mode, low 29 bits payload
  word offset. Modes 0..5: zero, solid, 2-color, 4-color, 16-color, 64-literal.
  Payload lengths are 0, 1, 4, 8, 24, 64 u32 words respectively. Palette entries come
  first, then 1/2/4-bit row-major indices, least significant bits first. Palette
  order is first appearance and unused palette slots are zero.
  Edge blocks repeat the final valid row/column; reads obey surface dimensions.
  A nonempty aligned surface costs at most 4.0625 bytes/pixel, not guaranteed
  compression. Directory and exact used payload are retained, not output capacity.
  Whole-surface zero descriptor retains no GPU buffers. Prefix sum 0 proves all
  final RGBA words are 0 because every other block mode contributes >= 1 word.
  The descriptor is 16 logical scalar bytes, separately from pixel-buffer counts;
  JavaScript object and driver allocation overhead are not given artificial sizes.
  Current maximum is 16,384 blocks (1024x1024 aligned pixels) per bounded batch.
  GPU analysis/prefix scratch is 12 bytes/block + 260 bytes; host uses 28 additional
  bytes of uniform, count-staging and placeholder bindings. Exact output sizing
  introduces one GPU-to-CPU count-read wait per batch; reported timings include it.

Mip atlas
  Each input is one 349,525-u32 buffer containing 512², 256², ..., 1² completed pixels.
  Three chains occupy 1,048,575 of 1,048,576 atlas pixels. Their explicit per-level
  rectangles are disjoint; the final unused pixel and absent chains are zero.
  Sources require <= 4 MiB, atlas 4 MiB. Caller releases both after compact encoding.
  Display reads stored final pixels; mip generation and all-nine readiness belong
  to the upstream generator. Above-page/world mip completeness is not claimed here.

Provenance and validation
  Original implementation for Noitamap; project license applies. These are integer
  lossless storage/packing operations, not decompiled game routines.
  Native Dawn 0.6.2 with Mesa 25 llvmpipe software Vulkan validated all encoder modes,
  partial blocks, hidden RGB, full prefix extent and 1/2/3-page mip atlases. GPU
  directory/payload bytes match CPU encoder, and decoded RGBA matches every input.
  Scratch reproducible harness: task/native-biome-runtime/storage/.
  Complete Mines seed 20261016 independent terrain/composition/edge oracle matched
  all 108 pages and 1,080 page-mip surfaces, 150,994,800 bytes, after GPU encoding and
  decoding. This is a complete-biome current-reference check, not all-nine proof.
  Active 16 atlases: 67,108,800 raw bytes to 17,327,900 retained bytes (~3.87x).
  Twenty additional completed atlases are exactly zero and use scalar descriptors.
  No weak-machine hardware or browser performance is inferred from software Vulkan.
